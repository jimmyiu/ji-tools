## 6. Promote candidates → long-term learning

- [ ] 📌 **vitest.config.ts requires duplicate Vite `define` block** → **Promote to project AGENTS.md** (`AGENTS.md` 的 Architecture notes section)
  > **Why**: Vite `define` in vite.config.ts is not inherited by vitest when using separate config files. This caused a test failure that was only caught at the third step of the cycle.
  > **How to apply**: When adding `define` entries to `vite.config.ts`, always add the identical `define` block to `vitest.config.ts`. Tests will fail silently otherwise.

- [ ] 📌 **deploy.yml and release.yml use different action versions** → **One-off** (record only, no structural change needed)
  > **Why**: The inconsistency between `@v4` (release.yml) and `@v6` (deploy.yml) arose because release.yml was created from plan.md spec (which specified `@v4`) while deploy.yml inherited existing `@v6` versions. Both are functional.
  > **How to apply**: When creating new workflows, check existing workflows for the current action version convention rather than relying solely on plan specs.
